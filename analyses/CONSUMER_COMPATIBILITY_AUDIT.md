# Consumer compatibility audit — 26 October 2026

This is the completed broader audit authorized after the older-form CLI regressions and the
[signature feedback follow-up](PLAN_3_PREVIEW_REGRESSIONS.md). It supplements the
[Plan 3 final review](PLAN_3_FINAL_REVIEW.md); it does not replace its device acceptance or security
checkpoint. Checks use current source candidates, not a claim about published registry contents.

## Result and boundaries

The authoritative catalogs contain **32 builtins and 18 field types**. New coverage manifests are
checked against the installed catalogs, and the field fixture is traversed to prove that every field
type actually occurs in its schema. The audit exercises all 26 implemented calculation expressions
and all 23 shared event expression helpers in TRUSTED and SAFE, alongside ON, OFF, ALERT, SETVALUE
and INVALID. FORM is explicitly classified as an existing placeholder and tested for its documented
execution failure in core. Nothing here implements FORM or widens calculation/event permissions.

The same portable fixtures run through core, CLI HTTP sessions and actual browser controls, React
main-thread and actual browser workers, and the Native renderer adapter. Full existing suites cover
the deeper scope, collection, condition, lifecycle and submission contracts. This is representative
compatibility coverage, not every possible builtin/field/expression cross-product.

## Known limitations and release ownership

- FORM remains the explicit unsupported placeholder; execution failure stays separate from intrinsic
  field errors. This audit does not silently make it work or substitute a value.
- Standalone FormLink selection controls remain placeholders; host-supplied selected references
  round-trip. The audit does not add a record picker or new reference normalization.
- Arbitrary stored media does not gain a new loader/hydration provider in CLI. Programmatic clearing
  of already displayed captures is fixed. Video race coverage controls metadata completion and does
  not claim a real codec/browser-decoder matrix.
- Public reader contracts are unchanged, so no localized public documentation was changed by this
  audit. COUNTA's existing documented runtime behavior is retained. No local docs production build ran.
- Dependency/security evidence remains that of the prior security pass; no new clean audit is claimed
  from these behavior checks. The maintainer-selected CLI publication hold for Pi/Undici remains.
  Native/mobile exception remediation remains separate.
- Commits stay on existing development branches. Maintainer dependency/funding edits remain unstaged.
  Version bumps, publication, pushes, promotion merges, deployment and issue closure are maintainer-owned.
