# AI-Ready Foundations for form0-core

## Phase 1 (completed)

- **Schema metadata scaffolding**
  - Optional `form.ai` and `field.ai` objects recognised across all field specs.
  - Dedicated validator (`src/schema/ai-metadata-validator.js`) enforces allowed keys, string/array shapes, naming & choice policy constraints, and boolean governance flags.
  - Schema validation (`validateSchema`) and field registry (`validateFieldSchema`) now surface friendly errors when AI metadata is malformed.
- **Read APIs**
  - Utility accessors in `src/utilities/ai-metadata.js` normalise context/instruction arrays, expose naming & choice policies, provider hints, etc., and are exported from `src/index.js`.
- **Fixture coverage**
  - Primary test schema (`tests/form0-core.test.js`) includes representative AI blocks (form-level context/policies, field-level instructions/examples/choicePolicy) with assertions verifying the helpers.
- **CLI parity**
  - CSV import/export supports `form.ai` and leaves field `ai` attributes empty unless populated, preventing `ai: null` noise.

## Phase 2 (planned next)

- **Provider contract scaffold**
  - Define an `AIProvider` interface (e.g., `requestSuggestions`, `requestValidation`) and thread configuration through `createFormEngine`.
  - Provide a mock provider in tests to keep deterministic behaviour.
- **Async orchestration hooks**
  - Introduce engine hooks so evaluation cycles can enqueue AI tasks without blocking core logic.
  - Emit structured events (`ai:suggest-*`) gated behind config.
- **Governance & observability**
  - Persist provenance (model, prompt hash, timestamp) for AI-derived values.
  - Add audit-safe logging hooks and configurable consent/redaction policies leveraging existing security config.

## Phase 3 (future roadmap)

- **Utility layer**
  - Implement `createAIContext` and related prompt builders that merge schema, state, and metadata with redaction helpers.
  - Ship `generateNamingSuggestions` and `applyAISuggestions` utilities that combine deterministic policies with provider results.
  - Maintain a versioned `FIELD_AI_GUIDE` describing baseline instructions per field type.
- **Storage & caching**
  - Abstract prompt/result caching so reform can plug in device or cloud stores transparently.
- **Expanded testing**
  - Add CLI round-trip coverage for `form.ai` and field metadata.
  - Provide sample schemas + scripts demonstrating AI-enabled workflows for reform integration.

## Principles & guardrails

- Optional metadata; existing consumers operate unchanged when `ai` is absent.
- No executable content in `ai.*`; all suggestions still flow through established validators.
- Provider orchestration remains outside form0-core; reform or other hosts supply the actual AI runtime when ready.
